# 8. Как да променям програмата — готови рецепти

**Златно правило:** преди промяна направете копие на проекта (и резервно копие на базата от панела).
Променяйте по една малка неща и веднага проверявайте в браузъра.

## 1. Как да видя грешките

1. В `.env` сложете `APP_DEBUG=true` (само докато разработвате!). Грешките се показват подробно.
2. Дневникът е в `storage/logs/laravel.log` — най-долу е последната грешка.
3. На жив сайт върнете `APP_DEBUG=false`.
4. След промяна на `.env` или `config/*` понякога трябва да изтриете `bootstrap/cache/*.php`.

## 2. Промяна на цветове и шрифтове

Файл: `public/assets/css/site.css`. Най-горе има блок `:root { … }` с променливи
(`--accent`, `--bg`, `--text`…). Сменете стойностите — променя се целият сайт.
Панелът е в `admin.css`.

## 3. Промяна на текст от интерфейса (напр. „Прочети още“)

Без код: панел → **Преводи** → потърсете ключа → сменете текста.

Нов текст:
1. В шаблона напишете `{{ t('moy.klyuch') }}`.
2. Добавете ключа в панела (Преводи) или в `database/seeders/strings.php` (за нови инсталации).

## 4. Нов език

Панел → **Езици** → Добави (код `de`, име). После в **Преводи** попълнете текстовете,
а при всяка страница се появява нов раздел за езика. Нищо в кода не се пипа.
Код от 2 букви (`de`) става префикс в адреса (`/de/…`).

## 5. Промяна на роли и права

Файл: `config/mcms.php`, секция `roles`. Пример — авторите да виждат и категории:

```php
'author' => ['content', 'media', 'categories'],
```

Имената на правата са в `routes/web.php` (`admin:content`, `admin:menus` …).

## 6. Ново поле на страниците (пример: „подзаглавие“)

1. **Нова миграция** (не пипайте старата!): `database/migrations/2026_02_01_000001_add_subtitle.php`

```php
<?php
use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration {
    public function up(): void {
        Schema::table('content_translations', function (Blueprint $t) {
            $t->string('subtitle')->nullable();
        });
    }
    public function down(): void {
        Schema::table('content_translations', fn (Blueprint $t) => $t->dropColumn('subtitle'));
    }
};
```

2. В модела `app/Models/ContentTranslation.php` добавете `'subtitle'` в `$fillable`.
3. Във формата `resources/views/admin/content/form.blade.php` добавете `<input name="tr[{{ $code }}][subtitle]">` до заглавието.
4. В `Admin/ContentController.php` (валидацията) добавете правило `'tr.*.subtitle' => 'nullable|string|max:255'`.
5. В `app/Support/ContentSaver.php` добавете `subtitle` към полетата, които се записват.
6. В `resources/views/site/page.blade.php` покажете: `{{ $tr->subtitle }}`.
7. **Изпълнете миграцията:** на хостинг без SSH — изпълнете SQL в phpMyAdmin:
   `ALTER TABLE content_translations ADD subtitle VARCHAR(255) NULL;`
   (с SSH/локално: `php artisan migrate`).

## 7. Нов раздел в админ панела (пример: „Партньори“)

1. Миграция + модел `app/Models/Partner.php`.
2. Контролер `app/Http/Controllers/Admin/PartnerController.php` (по образец на `RedirectController` — най-прост).
3. Маршрути в `routes/web.php`, в админ групата — копирайте блока на `redirects` (ред ~83) и сменете имената:
   `Route::middleware('admin:partners')->prefix('partners')->name('partners.')->group(function () { … });`
4. Шаблони в `resources/views/admin/partners/` (копирайте `redirects`).
5. Право `partners` в `config/mcms.php` за ролите, които имат достъп (админът има `*`).
6. Връзка в менюто на панела — във файла `resources/views/admin/layout.blade.php` (масивът с менюто).
7. Не забравяйте `audit('partner.create', …)` при запис.

## 8. Нов плъгин

Папка `plugins/moy-plugin/` с два файла:

`plugin.json`
```json
{ "name": "Мой плъгин", "version": "1.0.0", "description": "Какво прави" }
```

`plugin.php`
```php
<?php
// добавя текст в края на всяка страница
add_action('footer', function () {
    echo '<p>Здравей от плъгина</p>';
});
```

Качете папката по FTP → панел → **Плъгини** → Включи.
Налични хукове: `head`, `footer`, `content.body` (филтър), `content.saved`, `contact.received`,
`user.login`, `admin.menu`, `site.menu`. Вижте `plugins/schema-org/` като пример.

## 9. Нова позиция на меню

В `Menu` позициите са `header` и `footer`. За нова (напр. `sidebar`): добавете запис в таблица `menus`
(колона `location`), покажете я с `Menu::tree('sidebar')` в `AppServiceProvider` (view composer) и в шаблона.

## 10. Промяна на лимитите

`.env` / `config/mcms.php`: `MCMS_MAX_UPLOAD_MB`, `MCMS_IDLE_MINUTES`, `MCMS_ADMIN_PATH`.
Обърнете внимание: PHP също има свои лимити (`upload_max_filesize`, `post_max_size`).

## 11. Често допускани грешки

| Грешка | Решение |
|---|---|
| Промених `.blade.php` и няма ефект | Изтрийте `storage/framework/views/*.php` |
| `Class not found` | Липсва `use …;` най-горе или грешно име/namespace |
| 419 Page Expired | Във формуляра липсва `@csrf` или сесията е изтекла |
| 403 при запис | Ролята няма това право (`config/mcms.php`) |
| Нова колона „не се записва“ | Не е добавена в `$fillable` на модела |
| Нова колона липсва в базата | Не е изпълнена миграцията (рецепта 6, стъпка 7) |

## 12. Редакторът (CKEditor 5)

Полето „Съдържание“ е **CKEditor 5** (безплатна GPL версия, всички безплатни плъгини). Файлове:

| Файл | Роля |
|---|---|
| `public/assets/vendor/ckeditor5/` | Самият CKEditor (не се пипа). Лиценз: `LICENSE.md`, `COPYING.GPL` |
| `public/assets/js/editor.js` | Нашата настройка: кои плъгини, какви бутони, български, бутон „Медия“ (библиотеката) |
| `app/Support/Sanitizer.php` | Какво от HTML-а на редактора се пази при запис |

**Добавяне/махане на бутон:** в `editor.js` — масив `toolbar.items`. Плъгинът трябва да е и в `names`.

**Важно:** всичко, което редакторът произведе, минава през `Sanitizer`. Ако добавите нов плъгин и
резултатът „изчезва“ след запис — Sanitizer не го разрешава. Разширете `TAGS`, `ATTRS` или `STYLE_PROPS`
в `Sanitizer.php` и пуснете `php tests/standalone.php`.

**Видео:** YouTube/Vimeo се записват като `<oembed url="…">`, а при показване се превръщат в iframe
(`Sanitizer::renderEmbeds`, извиква се от `mcms_body()` в `app/helpers.php`).

**Стилове на съдържанието** (подравняване, маркери, снимки, таблици) са в края на `public/assets/css/site.css`.

**Не са включени** умишлено: Emoji (тегли данни от външен CDN), платените/облачни функции, качване на снимки
директно в редактора (ползвайте бутона „Медия“), HtmlEmbed, TodoList, Bookmark.

**Лиценз:** CKEditor 5 е GPL. За личен сайт няма проблем; ако продавате/раздавате системата на клиенти,
прочетете https://ckeditor.com/legal/ckeditor-licensing-options .

## 13. Редове и колони в редактора (бутон „Колони“)

В лентата на редактора има бутон **„Колони (ред)“** → избирате от 1 до 12 колони. Ред се вмъква в текста; във всяка колона пишете като в нормален текст
(заглавия, снимки, таблици…). Останалите бутони (активни, когато курсорът е в колона):

| Бутон | Какво прави |
|---|---|
| Ширина на колоната | Колоната заема 1–12 „части“ от реда (напр. ред с 4 части: колони 1+2+1) |
| Добави колона / Премахни колоната | Променя броя колони (1–12) |
| Изтрий целия ред | Маха реда с всичко в него |

Записва се като `<div class="mc-row mc-cols-3"><div class="mc-col mc-span-1">…</div>…</div>`.
Стилове: `public/assets/css/grid.css` (зарежда се и в сайта, и в редактора). **Responsive:** над 900px — както е зададено;
641–900px — по 2 колони; до 640px — една под друга. Код на плъгина: `public/assets/js/editor-grid.js`.
Ред в ред (вложени редове) не е позволен.

## 14. Тагове и свързани публикации

**Тагове** (само за публикации): в формата на публикацията, карта „Тагове“ — пишете със запетая (`php, laravel`);
нови тагове се създават сами. Съществуващите се добавят с клик. Меню **Тагове** — превод на име/slug по езици, обединяване и изтриване.
На сайта: под статията са връзки към `/blog/tag/име`, а страницата на тага е списък с публикациите (като категория).

**Свързани публикации:** карта „Свързани публикации“ — започнете да пишете заглавие и изберете. Под статията се показват:
1) ръчно избраните, 2) после публикации с най-много общи тагове, 3) после от същата категория. Броят е в *Настройки → Свързани публикации*
(0 = изключено).

**Файлове:** `database/migrations/2026_02_01_000001_add_tags_and_related.php` (таблици `tags`, `tag_translations`, `content_tag`, `content_related`),
`app/Support/Taxonomy.php` (логика и алгоритъм), `app/Models/Tag*.php`, `Admin/TagController.php`, `SiteController::tag()`, `routes/web.php`.

**Обновяване на съществуваща инсталация (без SSH):** качете новите файлове → в панела на таблото натиснете **„Обнови базата“**
(или Тагове → „Обнови базата“). Алтернатива: изпълнете `database/upgrade/4.2-upgrade.sql` в phpMyAdmin.
Докато базата не е обновена, сайтът работи както преди, а картите за тагове показват подсказка.

## 15. Кошче (soft delete)

Страниците, публикациите и категориите **не се трият веднага**: „Изтрий“ ги мести в кошчето (колона `deleted_at` в базата).
- Страници / Публикации → таб **Кошче**: „Възстанови“, „Изтрий завинаги“, „Изпразни кошчето“.
- Категории → секция „Кошче“ най-долу. Публикациите запазват категорията си, затова при възстановяване всичко се връща.
- В кошчето записите не се виждат в сайта, търсенето, sitemap и менютата. Адресите (slug) им остават заети.
- Команда за автоматично чистене: `php artisan mcms:purge-trash 30` (трие завинаги по-стари от 30 дни; може да се сложи в cron).
- Код: `app/Models/Concerns/Trashable.php` (пази се от срутване, ако базата още не е обновена) и `app/Support/Trash.php`.
- Обновяване на съществуваща инсталация: бутон „Обнови базата“ на таблото или `database/upgrade/4.2-upgrade.sql`.

## 17. Дизайн (Настройки → таб „Дизайн“)

Всичко се пази в таблицата `settings` с ключове `design.*` — **не е нужна миграция**.
Генерираният CSS се сервира от `/design.css?v=…` (CSP-съвместимо, без инлайн стилове) и се зарежда след `site.css`.

| Група | Какво настройвате |
|---|---|
| Цветове | фон, текст, заглавия, акцент, фон на хедър и футър. Празно = цвят на темата. Ако зададете само фон или само текст, другият се избира автоматично за контраст |
| Шрифтове | основен, заглавия, меню, лого; базов размер 14–22 px. Само системни шрифтове (без външни заявки) |
| Лого и хедър | височина на логото `auto` или 20–300 px; sticky (залепен) хедър вкл./изкл. |
| Анимация на страницата | 6 типа (избледняване, 4 посоки, увеличение), скорост в ms, **ключ вкл./изкл.**, по желание бутон „Спри анимациите“ за посетителите (пази се в браузъра им) |
| Анимации на елементи | отделен тип за: хедър, лого, менюта, карти, изображения, заглавия в текста, футър. Показват се при скролиране до елемента. **Главен ключ** ги спира всички |
| Top-bar | вкл./изкл., 1–4 колони, подравняване и съдържание за всяка колона и всеки език (текст или HTML: връзки, удебеляване, икони Font Awesome), цветове, показване на телефон |

- Посетители с включено „намалено движение“ в устройството не виждат анимации, каквото и да е зададено.
- „Върни дизайна по подразбиране“ изтрива всички `design.*` настройки.
- Код: `app/Support/Design.php` (стойности, валидиране, CSS), `Admin/SettingController::updateDesign`, `resources/views/admin/partials/design-form.blade.php`, `public/assets/js/site.js` (анимации), `site.css` (top-bar, keyframes).
- Нов шрифт: запис в `Design::FONTS`. Нов елемент за анимация: `Design::ELEMENTS` + селектор в `SELECTORS` в `site.js` + ключ `el_<име>` в `Design::DEFAULTS`.

## 18. Качване на снимки (постове, страници, редактор)

Снимки могат да се качват директно, без да се минава през „Медия“:

- **В CKEditor:** бутон „Качване на изображение от компютър“, влачене на файл върху текста или поставяне (Ctrl+V) на снимка. Файлът отива в библиотеката и се вмъква в текста.
- **Поле „Изображение“ на пост/страница** (и лого/favicon в Настройки): бутон **⬆ Качи** или влачене на снимка върху полето. „Библиотека“ отваря вече качените файлове.
- **Прозорец „Библиотека“:** бутон **⬆ Качи** (един файл се избира веднага; няколко само се добавят) или влачене върху прозореца.

Всяко качване минава през `Uploader` (проверка на типа, пре-кодиране с GD, случайно име). Ендпоинти: `POST /panel/media/upload` (JSON) и `POST /panel/media/editor-upload` (за CKEditor, само изображения).
Лимит: `MCMS_MAX_UPLOAD_MB` в `.env` (8 MB), но хостингът има свой — `upload_max_filesize` и `post_max_size` в PHP. При грешка 413 вдигнете ги.

## 19. Автоматично преобразуване на снимките във WebP

При качване (библиотека, полета „Изображение“, CKEditor) всяка снимка **JPG, PNG и статичен GIF** се преобразува във **WebP** и се записва в таблица `media` като `image/webp` (с новия размер, ширина и височина). Умалената версия (thumb) също е WebP.

- JPG → WebP със загуба, качество от Настройки → Общи → „Качество на WebP“ (по подразбиране 82).
- PNG и GIF → WebP **без загуба** (запазва прозрачността и острите ръбове).
- Анимираните GIF-ове остават GIF (WebP от GD не поддържа анимация). PDF не се променя.
- Изключва се от Настройки (отметката „Преобразувай качените снимки във WebP“). Ако GD на хостинга няма WebP, качването продължава в оригиналния формат.
- Вече качените снимки **не се преобразуват** — само новите.
- Код: `app/Support/Uploader.php` (`webpTarget`, `reencode`).

## 20. Премахната двуфакторна защита (2FA)

В 4.2 няма 2FA: входът е с имейл и парола (с ограничение на опитите, заключване на акаунта, автоматично излизане и привързване към браузър). Махнати са страницата за код, секцията в Профил, настройката „задължителна 2FA“, командата `mcms:reset-2fa` и класа `Totp`.
Ако при вас е имало включена 2FA, тя просто спира да се изисква. Колоните `totp_*` в `users` остават неизползвани и не пречат — не е нужна миграция.

## 21. Коментари (Настройки → Дискусии)

Система за коментари под публикации и страници, подредена като **Settings → Discussion** на WordPress. Таблица `comments` + колона `contents.comments_open` се създават с бутона **„Обнови базата“** (Табло) или с `database/upgrade/4.2-upgrade.sql`.

**Настройки (таб „Дискусии“)**
- **Главен ключ вкл./изкл.** — изключено: няма форма и вече написаните коментари не се показват.
- По подразбиране: коментари под нови публикации / страници; име и имейл задължителни; поле „Уебсайт“; аватари (Gravatar, по подразбиране изключени — пращат хеш на имейла към gravatar.com).
- Вид: автоматично затваряне на коментарите по-стари от N дни, коментари на страница, ред (стари/нови първо), вложени отговори до 5 нива.
- Известия по имейл: нов коментар / коментар чака одобрение (до имейла за контакт).
- Преди появяване: всеки коментар ръчно; авторът трябва да има вече одобрен коментар.
- Модерация и спам: задържане при N или повече връзки, ключови думи за модерация, забранени думи (→ „Спам“), пауза между коментари от един IP.

**Поотделно за всяка страница/публикация:** кутия „Дискусия“ в редактора — По подразбиране / Отворени / Затворени.

**Управление:** меню „Коментари“ (брояч на чакащите) — табове Всички / Чакащи / Одобрени / Спам / Кошче, масови действия, търсене, редакция, отговор от панела. Спам и кошче се чистят от `php artisan mcms:purge-trash`.

**Защити:** CSRF, скрито поле-капан, проверка на времето (≥3 сек), ограничение на опитите по IP, откриване на дубликати, текстът се записва като чист текст и се показва екраниран (връзките получават `rel="nofollow ugc"`). Членовете на екипа, влезли в панела, публикуват без модерация.

Код: `app/Support/Discussion.php`, `CommentController` (публичен), `Admin/CommentController`, изгледи `site/partials/comments*.blade.php`, `admin/comments/*`, `admin/partials/discussion-form.blade.php`.
Не са включени (за разлика от WordPress): pingbacks/trackbacks, регистрирани читатели, Akismet.

## 22. CSS клас и ID на елементите от менюто

В **Менюта → редакция** всеки ред има полета **CSS клас** (един или няколко, с интервал) и **ID**. Добавят се към `<li>` на елемента (както в WordPress), във хедъра (и в падащото подменю) и във футъра:

```html
<li class="has-sub btn highlight" id="menu-shop"><a href="/shop">Магазин</a> …</li>
```

```css
#menu-shop > a { font-weight: 700; }
.highlight > a { color: #c00; }
```

- Клас: букви, цифри, `-` и `_`, не започва с цифра. ID: започва с буква, без интервали, **уникален** в менюто (дублиране се отхвърля).
- Опасни символи (кавички, `;`, `<`) се отказват при запис и се филтрират и при показване.
- Нужна е колоните `css_class`, `css_id` в `menu_items` — бутон „Обнови базата“ (Табло) или `database/upgrade/4.2-upgrade.sql`. Докато не е направено, полетата не се показват, а менютата работят както преди.
- Код: `MenuItem::cleanClass/cleanId`, `Admin/MenuController`, `site/layout.blade.php`.

## 23. Уиджети: футър с колони и сайдбар на блога

**Настройки → Футър / Сайдбар.** Без миграция — всичко е в `settings` (JSON).

- **Футър:** избор на 0–12 колони (0 = стандартният футър). Във всяка колона се добавят уиджети, подредени с ↑ ↓.
- **Сайдбар:** вкл./изкл., страна (ляво/дясно). Показва се **само в блога** (списък, категория, таг, публикация) — не на страници. На телефон отива под съдържанието.
- **Типове уиджети:** Текст/HTML (с Font Awesome — бутон за икони), Меню (избира се меню по местоположение), Последни публикации (брой, дата, снимка), Категории, Тагове (облак/списък), Последни коментари, Търсене, Социални мрежи.
- Всеки уиджет: заглавие по езици, икона, CSS клас. HTML се чисти от Sanitizer-а при запис.
- Ако колоните са празни → стандартният футър. Текстът „Текст във футъра“ остава най-долу.
- Код: `app/Support/Widgets.php`, `Admin/SettingController::updateFooter/updateSidebar`, `admin/partials/{footer-form,sidebar-form,widget-card,widget-area}`, `site/partials/widget-area`, `site/widgets/*`, `site/layout.blade.php`, JS в `admin.js`. Нов тип: добавете го в `Widgets::TYPES`, `clean()`, `widget-card` и `site/widgets/<тип>.blade.php`.

## 24. Настройки като в WordPress (Четене, Писане, Дата и час, Връзки, Медия, Скриптове, Поддръжка)

Табове в **Настройки** (само администратор). Без миграция — ключове `opt.*` в `settings`. Логика и валидация: `app/Support/Options.php` (тестове в `tests/standalone.php`); формите са в `admin/partials/options/*.blade.php`, запис — `SettingController::updateOptions`.

| Таб | Какво прави |
|---|---|
| Четене | начална = статична страница или последни публикации; брой и пълен текст в RSS; дължина на откъса; „скрий от търсачките“ (meta noindex + `robots.txt` Disallow) |
| Писане | категория и статус по подразбиране за нова публикация |
| Дата и час | часова зона (внимание: измества вече записаните дати), формат на дата и час — `mcms_date()` в шаблоните |
| Връзки | адрес на блога, префикс на категории и тагове (`/blog/category/x` → напр. `/news/topics/x`); старите адреси се пренасочват с 301 (`Options::legacyPath`) |
| Медия | макс. размер на файл, макс. страна на изображение, ширина на миниатюра (празно = от `config/mcms.php`/`.env`) |
| Скриптове | код в `<head>` и преди `</body>` (auto CSP nonce) + списък с разрешени външни https адреса за script-src/connect-src |
| Поддръжка | съобщение на 503 страницата и IP адреси, които винаги виждат сайта (режимът се включва в „Общи“) |

- Връзки: имената на маршрутите (`blog`, `category`, `tag`, `post`) са същите, затова менюта, карти и sitemap следват новите адреси сами. Адресът на блога не може да е системен (`search`, `panel`…), двубуквен или съвпадащ със съществуваща страница.
- Скриптове: външен скрипт работи само от адрес в списъка (CSP). Не добавяйте непознати домейни.
- Часова зона се прилага в `AppServiceProvider::applyOptions()`.

## 25. Регистрация, роли като в WordPress, резюме и страница на автора

**Настройки → Потребители:** „Всеки може да се регистрира“ (страница `/register`), роля на новите потребители, одобрение от администратор, имейл известия. Нужна е миграцията `2026_03_03_000001_add_user_profile` (бутон „Обнови базата“ или `database/upgrade/4.2-upgrade.sql`) — до тогава регистрацията е изключена, а всичко останало работи.

| Роля | Може |
|---|---|
| Абонат | само профил и резюме |
| Сътрудник | пише свои статии; „Публикувана“ става „Чака одобрение“; не редактира вече публикувана; няма медия |
| Автор | пише, редактира и публикува свои статии; качва медия |
| Редактор | всички статии и страници, одобрява чакащите, категории, меню, коментари |
| Администратор | всичко |

- Страниците (`pages`) и настройките са само за редактор/администратор (преди авторите имаха достъп до страници).
- Статус `pending` („Чака одобрение“): филтър в списъка, брояч на таблото, имейл до администратора.
- **Резюме:** Моят профил → „Резюме“ (CKEditor, чисти се от Sanitizer) + уебсайт. Показва се на `/author/{username}` (с неговите статии) и като кутия „За автора“ под статията. Параметър в Настройки → Четене: „Показвай автора“.
- Уиджет „Вход / Регистрация“ за футъра/сайдбара.
- Код: `RegisterController`, `app/Support/Members.php`, `Admin/ProfileController::updateBio`, `SiteController::author`, `site/{register,author}.blade.php`, `site/widgets/account.blade.php`, `ContentController` (pending/права).
- Защита на регистрацията: CSRF, скрито поле + минимално време, 5 опита/час на IP, парола ≥ 10 знака. Няма потвърждение на имейл и „забравена парола“ (паролата се нулира от администратор) — при спам включете одобрението.

## 26. Езици на интерфейса (английски / български)

- **Панел, вход и инсталатор:** английски по подразбиране. Превключване с `?lang=en|bg` (или бутона EN/BG); изборът се пази в бисквитка `mcms_admin_lang` (1 година). Подразбиращ се език: `MCMS_ADMIN_LOCALE=en|bg` в `.env` (`config/mcms.php → admin_locale`).
- **Механизъм:** текстовете в кода са български ключове в `__('…')`; `lang/en.json` съдържа английските стойности (при `bg` се връща самият ключ — `fallback_locale = bg`). Валидация: `lang/en/validation.php`, `lang/bg/validation.php`.
- **JavaScript:** `window.T('…')` (`public/assets/js/i18n.js`); речникът идва от `lang/js.json` през `admin/partials/i18n.blade.php`; езикът на CKEditor следва `T.lang`.
- **Нов текст:** напишете го в `__('Български текст')` и добавете реда в `lang/en.json` (за JS — и в `lang/js.json`). Заместители: `:name` и т.н.
- **Публичният сайт** си има отделни езици (таблица `languages`, преводи от „Преводи“) — не зависи от езика на панела.
- Английската документация: `docs/en/`, `README.en.md`.
