# 4. База данни

Схемата е описана в един файл: `database/migrations/2026_01_01_000001_create_core_tables.php`.
Моделите са в `app/Models/` (по един за таблица).

## Обща картина

```
users ───────────────────────────────┐ (автор на съдържание, качил медия, действие в журнала)
                                     │
categories ──< category_translations │
    │                                │
    └──< contents >──< content_translations >──< revisions
            │  │
            │  └── featured_media_id ──► media
            └── (menu_items.content_id сочи към contents)

menus ──< menu_items

languages        (кои езици има)
translations     (преводи на интерфейса: ключ + език → текст)
settings         (настройки: ключ → стойност)
messages         (съобщения от контактната форма)
redirects        (пренасочвания)
audit_logs       (журнал на действията)
```

Знакът `──<` значи „едно към много“: една категория има много преводи; едно съдържание има много превода.

## Как е устроена многоезичността (най-важната идея)

Вместо да пазим заглавието в таблицата на страницата, го пазим в отделна таблица **по един ред за език**:

**contents** (общо за страницата)

| id | type | status | publish_at | is_home |
|----|------|--------|------------|---------|
| 7 | page | published | 2026-10-01 | 0 |

**content_translations** (специфично за езика)

| id | content_id | locale | title | slug | body |
|----|-----------|--------|-------|------|------|
| 11 | 7 | bg | За нас | za-nas | `<p>…</p>` |
| 12 | 7 | en | About us | about-us | `<p>…</p>` |

Адресът на английската версия е `/en/about-us`, а на българската — `/za-nas`. Така всеки език има **свой** адрес (добре за търсачките).
Същото важи за категориите (`categories` + `category_translations`).

## Таблиците една по една

### `users` — потребители на панела
| Колона | За какво е |
|--------|-----------|
| `name`, `email` | Име и имейл (имейлът е уникален) |
| `password` | Парола в **хеш** (необратимо „смляна“; никой не може да я прочете) |
| `role` | `admin`, `editor` или `author` |
| `active` | 0 = деактивиран |
| `totp_secret`, `totp_enabled`, `totp_last_step`, `recovery_codes` | Двуфакторна защита (тайната и кодовете са криптирани) |
| `failed_attempts`, `locked_until` | Брояч грешни пароли и време на заключване |
| `last_login_at`, `last_login_ip` | Последен вход |

### `languages`
`code` (`bg`, `en`), `name`, `native_name`, `is_default` (основен), `is_active`, `sort`.

### `translations` — текстовете на интерфейса
`key` (например `nav.blog`), `locale`, `value`. Уникално е съчетанието `key + locale`.
Така `t('nav.blog')` връща „Блог“ на български и „Blog“ на английски.

### `settings`
Най-простата таблица: `key` → `value`. Примери: `site_name`, `contact_email`, `maintenance_mode`,
`tagline.bg`, `tagline.en` (точката и езикът в ключа правят настройката езикова).

### `contents` и `content_translations`
Описани по-горе. Допълнителни колони в `contents`:

| Колона | Смисъл |
|--------|--------|
| `type` | `page` или `post` (страница или публикация) |
| `status` | `draft` (чернова) или `published` |
| `publish_at` | От кога е видимо. Бъдеща дата = насрочено |
| `category_id` | Само за публикации |
| `featured_media_id` | Главна снимка (към `media`) |
| `is_home` | Дали е началната страница (само една) |
| `noindex` | Скрий от Google |
| `author_id` | Кой я е създал |

### `revisions` — стари версии
Преди да презапишем заглавие/текст, старото се копира тук. Пазят се последните 20 на превод.
Връзка към `content_translations`.

### `categories` / `category_translations`
Категориите на публикациите; име, адрес и описание по езици.

### `media`
Качените файлове: `path`, `thumb_path` (умалена снимка), `original_name`, `mime`, `size`, `width`, `height`, `alt`.
Самите файлове са в `public/uploads/ГОДИНА/МЕСЕЦ/`.

### `menus` и `menu_items`
`menus`: `location` (`header`, `footer`). `menu_items`: елемент от меню.

| Колона | Смисъл |
|--------|--------|
| `type` | `content` (към страница), `builtin` (вграден: home, blog, contact, search), `custom` (свободен линк) |
| `content_id` | За тип `content` |
| `url` | За `custom` — адресът; за `builtin` — името |
| `labels` | JSON с текст по езици: `{"bg":"Начало","en":"Home"}` |
| `parent_id` | За падащо подменю (макс. 2 нива) |
| `sort`, `new_tab` | Подредба; отваряне в нов прозорец |

### `messages`
Съобщения от контактната форма: `name`, `email`, `subject`, `body`, `ip`, `locale`, `read_at`.

### `redirects`
`from_path` → `to_url` с код 301/302 и брояч `hits`. Прилагат се само когато адресът иначе би дал 404.

### `audit_logs`
Кой (`user_id`), какво (`action`), върху какво (`subject`), детайли, от кой IP и с кой браузър, кога.
Записите се чистят след 180 дни.

## Какво се случва при изтриване (каскади)

| Изтривате | Автоматично се изтрива / променя |
|-----------|---------------------------------|
| Съдържание | Преводите му, версиите им, елементите от менюта, които сочат към него |
| Категория | Преводите ѝ; публикациите остават без категория |
| Медия файл | Публикациите губят главната снимка (остава празно) |
| Потребител | Съдържанието остава, но без автор |
| Език | Преводите на интерфейса и съдържанието на този език (**внимание**) |

Това се нарича **външни ключове** (`foreignId(...)->constrained()->cascadeOnDelete()` в миграцията).

## Как се работи с базата от кода (три примера)

```php
// 1) Прочети настройка
setting('site_name');                      // „Моят сайт“

// 2) Намери публикувани публикации, най-новите първи
Content::visible()->where('type', 'post')->orderByDesc('publish_at')->get();

// 3) Запиши нещо
Message::create(['name' => 'Ана', 'email' => 'ana@primer.bg', 'body' => 'Здравейте']);
```

`visible()` е **scope** — наша кратка заявка в `Content`: „статус published и дата ≤ сега“.
Така не повтаряме тази логика на много места.
